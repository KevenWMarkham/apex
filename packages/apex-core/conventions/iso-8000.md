# ISO 8000 — Data Quality Convention

**Sprint 22 Task 22.6 — BL.P.154**
**Pinned version:** ISO 8000-61:2016
**Standard authority:** International Organization for Standardization (ISO)
**Binding pattern:** B (data model mirror — dimension semantics implemented in code, no standard text redistributed)

---

## What APEX implements

APEX implements the **dimension semantics** of ISO 8000 information-and-data-
quality management. Every canonical Silver row carries a per-row
:class:`apex_core.quality.DataQualityMetadata` block embedded in the
:class:`apex_core.envelope.CanonicalEnvelope`. The block scores six
ISO-8000-aligned data quality dimensions:

| Dimension | Code semantics | When it's set |
|-----------|---------------|---------------|
| **completeness** | Fraction of required fields populated, [0,1] | Set by the Bronze→Silver loader after schema check |
| **consistency** | Fraction of cross-field invariants satisfied, [0,1] | Set by Silver-stage rule engine |
| **accuracy** | Agreement with authoritative reference where one exists, [0,1] | Set by terminology-service round-trip / SOR-of-truth lookup |
| **currency** | Freshness score: 1.0 = real-time, decays with staleness, [0,1] | Set by the loader from `event_ts` vs. `ingest_ts` delta |
| **provenance** | Strength of source + transformation-chain attestation, [0,1] | Set by the loader; high if signed mirror, low if scraped |
| **conformance** | Agreement with the bound canonical / industry-standard schema, [0,1] | Set by the schema validator — passes ⇒ 1.0; soft warnings degrade |

Every score is `Optional[float]` in `[0.0, 1.0]`. **`None` means "not measured"** —
agents must treat `None` as *unknown* (not as 0.0) and apply HOTL escalation when
the score gates a downstream consequential decision.

## What APEX does NOT redistribute

The full ISO 8000 standard text (clauses, annexes, conformance criteria) is **not**
redistributed. APEX implements the dimension semantics in code; tenants needing
to attest ISO 8000 conformance for an audit must hold their own ISO licence and
obtain the standard documents directly from ISO.

The CI restricted-content scanner (`tools/check_restricted_terminology.py`)
fails the build if any verbatim ISO standard text is committed to the
monorepo.

## Where the metadata lives

```
CanonicalEnvelope
├─ event_id            (UUID)
├─ event_ts            (datetime)
├─ entity_id           (str)
├─ source_system       (str)
├─ source_system_ts    (datetime)
└─ quality             (DataQualityMetadata)
    ├─ completeness         Optional[float] in [0,1]
    ├─ consistency          Optional[float] in [0,1]
    ├─ accuracy             Optional[float] in [0,1]
    ├─ currency             Optional[float] in [0,1]
    ├─ provenance           Optional[float] in [0,1]
    ├─ conformance          Optional[float] in [0,1]
    ├─ iso8000_pinned_version  str = "8000-61:2016"
    └─ quality_assessed_at  Optional[datetime]
```

The `CORE_ENVELOPE_FIELDS` constant exposes the original five non-quality
fields for downstream code that wants to distinguish provenance from quality;
`ENVELOPE_FIELDS` exposes all six.

## How dimensions are scored

### completeness

```
completeness = (#populated_required_fields) / (#required_fields)
```

The loader knows which fields are required from the canonical schema's
field annotations. Optional fields don't count toward the denominator.

### consistency

```
consistency = (#satisfied_invariants) / (#declared_invariants)
```

Invariants are declared as Pydantic `model_validator` rules and as
companion DDL CHECK constraints. The Silver-stage rule engine evaluates
each rule and emits the ratio.

### accuracy

When an authoritative reference exists (e.g., `apex.hls.mcp.patientml.lookup_provider`
against NPPES, GTIN against GS1 GEPIR), the loader queries and scores
agreement. **No reference ⇒ leave None.** Don't fabricate a 1.0.

### currency

```
currency = max(0, 1 - (now - event_ts).total_seconds() / staleness_window)
```

Default staleness window is 24 hours (configurable per schema). 1.0 means
real-time; 0.0 means at-or-beyond the staleness window.

### provenance

A categorical-to-scalar mapping:

| Source posture | Score |
|----------------|-------|
| Signed CDC mirror, immutable provenance chain | 1.0 |
| Mirrored DB without signature | 0.85 |
| API ingest with source-system audit trail | 0.7 |
| Authenticated bulk file load | 0.5 |
| Unsigned bulk file or scrape | 0.3 |
| Manual-entry / spreadsheet | 0.1 |

Tenants can override the mapping; the default lives in
`apex_core.quality.PROVENANCE_DEFAULT` (TODO Phase 2).

### conformance

```
conformance = (#fields_passing_pattern_validation) / (#fields_with_bindings)
```

Counts only fields with `StandardRef` annotations. A field that uses
`Icd10Code` and gets `"X.99.999"` is non-conformant; `"E11.65"` passes.

## Composite + degraded helpers

```python
md = row.quality
overall = md.composite_score()      # equal-weight mean of measured dims, or None
fully_assessed = md.is_fully_assessed()
weak = md.degraded_dimensions(threshold=0.7)  # list[QualityDimension]
```

Agents use `degraded_dimensions(threshold=...)` to gate downstream
decisions — e.g., the cold-chain disposition agent refuses to emit a
"destroy" recommendation when `provenance < 0.7`, escalating instead.

## Pin-bump procedure

When ISO publishes a new edition (e.g., 8000-61:2026 supersedes 2016):

1. Update `STANDARDS["iso-8000"].apex_pinned_version` in `registry.py`
2. Update `DataQualityMetadata.iso8000_pinned_version` default in `quality.py`
3. Run `apex standards sync-catalog` to regenerate `catalog.yaml`
4. Run `apex standards bump iso-8000 --to 8000-61:2026 --dry-run` for impact
5. Update this document's pinned-version header
