# LICENSE-ATTRIBUTION — APEX-A (stub)

APEX-A is a stub package today; this attribution document is in place
**from the start** to reflect that APEX-A is a real, audit-defensible
sibling product to APEX-M and APEX-G.

## AWS products planned for integration

When APEX-A is commissioned and built, it will integrate with the
client's existing AWS investment using:

- **Amazon Web Services** — EC2, Lambda, ECS, EKS, S3, RDS, DynamoDB,
  Secrets Manager, KMS, IAM Identity Center, IAM Roles Anywhere,
  CloudTrail, CloudWatch, X-Ray
- **Amazon Bedrock** — Agents, AgentCore, Titan models, Titan Embeddings,
  Knowledge Bases, Guardrails
- **AWS Lake Formation + S3 + Glue + Athena** — data tier (Microsoft
  Fabric equivalent)
- **Amazon EventBridge + SNS + SQS** — event routing (Eventstream/
  Activator equivalent)
- **AWS Macie + GuardDuty + Security Hub** — classification + threat
  detection (Purview/Defender equivalent)
- **Amazon QuickSight** — BI surface (Power BI equivalent)
- **Amazon WorkSpaces / WorkDocs** — productivity (M365 equivalent
  where applicable)

## Independence posture

Per Deloitte's Microsoft Technology & Services Practice, this
attribution records that APEX-A:

- **Will not** be a redistribution of any AWS product
- **Will not** be positioned as preferred over APEX-M or APEX-G
- **Does not** have an alliance posture with AWS — APEX-A exists to
  honor a client's existing AWS investment when their cloud architecture
  board has approved that as their primary substrate
